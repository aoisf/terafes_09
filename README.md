# 開発・作業ガイド



## 【重要】開発・ファイル操作ルール

* 作業は必ず自分のブランチで行うこと

* 【厳禁】Windowsのエクスプローラーから直接ファイルを移動・名前変更・削除しないこと

  * EclipseのGitプラグイン（EGit）でリポジトリ管理・追跡を行っているため、エクスプローラーから直接触るとEclipse側の表示と実ファイルがズレ（未同期）、パッケージ宣言やimportの更新漏れ、Git管理情報の不整合が発生し、復旧が困難になります。

  * ファイルの追加・移動・名前変更・削除は、必ずEclipseのパッケージ・エクスプローラー上から行ってください。

* 【厳禁】外部ライブラリ（.jarファイルなど）の無断追加の禁止

  * プロジェクトは追加ファイルなし（JDK標準機能および標準のServlet/JSP APIのみ）で動作する構成を厳守してください。

  * 個人で勝手にJARを追加すると、ビルドパス（.classpath）の破損や環境差異による動作不良の原因になります。

  * どうしても追加のライブラリやJARを使いたい場合は、勝手に追加せず、必ず事前にチームメンバーへ相談してください。

* 【厳禁】次のファイルは編集しないこと

  * .classpath / .project / .gitignore / web.xml

  * 変更が必要な場合は、勝手に直さず事前に相談してください。

* 【厳禁】プロジェクト名（パチンコ）を変更しないこと

  * プロジェクト名がそのままURLの一部（/パチンコ/）になっているため、変更すると動作確認URLが変わり、全員の環境がズレます。

* ファイルの文字コードはUTF-8のまま変更しないこと（Eclipseの設定を変えない）

## 動作環境（全員これで統一）

* Eclipse：配布したものをそのまま使用（バージョンのアップデートや設定の変更はしない）

* サーバー：Tomcat10_Java21 のみ使用

  * 他のサーバー構成や他のJavaで起きた不具合は保証の対象外です。

* サーバー定義を追加・変更しないでください。


## アプリのファイル構成

* `src/main/java/controller/`: URLごとの画面表示と操作受付（Servlet）
* `src/main/java/model/`: ペットの状態と育成・玉数計算
* `src/main/webapp/WEB-INF/jsp/`: 画面。`parts/` はメイン画面で使う部品
* `src/main/webapp/css/`: 共通CSS、サブ画面共通CSS、画面ごとの色や装飾。`dashboard.css` はメイン画面のヘッダーとポップアップ
* `src/main/webapp/js/`: `control.js` はメイン操作と祭フィーバー、`care.js` はごはん・あそぶ共通操作、`pachinko.js` と `rescue.js` は演出・救済操作、`dashboard.js` は図鑑・設定・記録・実績の操作
* `src/main/webapp/js/image-preview.js`: 画像の拡大表示、各画面での無操作監視、呼び込みモード。呼び込み画面の装飾は `css/common.css` にあります。
* `src/main/java/model/PlayRecord.java`: 展示中の操作記録、実績状態、選択中の育成ルーム背景をセッション内で保持
* `src/main/java/controller/BackgroundServlet.java`: 背景獲得後の育成ルーム背景変更
* `src/main/webapp/images/`: キャラクター、育成コマンド、育成ルーム背景（部屋・森・プール・太平洋・宇宙）

背景実績の必要操作回数は、森100回、プール500回、太平洋2,500回、宇宙12,500回です。各段階で前の背景の5倍に設定しています。
* `build/`: Eclipseのコンパイル結果や一時ファイル。Gitには含めない

JSPは `WEB-INF` 配下に置き、画面のURLは対応するServletから転送します。画面操作のJavaScriptは `js/` に置き、JSPへ長いスクリプトを直接埋め込まないようにします。

## アクセスURL

* 動作確認URL:

  http://localhost:8080/パチンコ/main?reset=true

  * ?reset=true を付けると、玉数・レベル・服・プレイ記録・背景などのセッション内のデータが初期状態に戻ります。

* 正常に動いている状態の目安:

  * 育成ルーム（たまごろう）、パチンコ画面、SPINレバー、育成コマンド（ごはん／あそぶ／おきがえ）が表示される。

  * SPINレバーを押すと玉が10発減る（当たれば増える）。

## 展示中の操作と演出

* オートを選択してレバーを押すと、10ms間隔で高速回転します。もう一度レバーを押すと停止します。設定でオートを初期選択していても、レバーを押すまでは回転しません。
* 玉が10発未満になったら救済ゲームを利用できます。救済ゲームで条件を達成し、報酬を受け取って再開してください。
* ごはん・あそぶで育成し、おきがえで服を変更できます。図鑑・記録・実績・背景は上部メニューから確認します。
* 画像をクリックすると拡大表示できます。閉じるボタンまたはEscapeキーで戻れます。

### お祭りフィーバー

* 玉を消費できた1スピンにつき、0.1％の確率で発動します。大当りの判定とは別です。
* 提灯・花火・紙吹雪・タイトルと、たまごろうの跳ねるリアクションを9秒間表示します。演出中に再当選すると、終了時刻がその時点から9秒後に延長されます。
* 演出によって払い出し倍率は変わりません。
* 設定 → お祭りフィーバー →「演出を見る」で、玉を消費せずプレビューできます。

### 呼び込みモード

* 5分間操作がなければ、ゲームのデータをリセットして呼び込み画面に切り替わります。メイン・ごはん・あそぶ・おきがえの各画面が対象です。
* クリック・タッチ・キー入力・ホイール操作で無操作時間を更新します。オート回転やマウスを動かすだけの操作では更新しません。
* レベル1のたまごろうと夜祭りの演出、遊び方を表示します。「タッチして はじめる」で初期状態のゲームを開始できます。
* 設定 → 呼び込みモード →「演出を見る」でプレビューできます。プレビューではゲームのデータは消えませんが、オート回転は停止します。
* ブラウザーやPCが休止している間は切り替えが遅れることがあります。画面復帰時に無操作時間を確認します。

### 展示前の確認

* 展示するPCで長時間動かし、手動・オート回転、育成・進化、おきがえ、救済ゲームを確認してください。
* 祭フィーバーと呼び込みのプレビュー、5分無操作後のリセット、呼び込みからの開始を確認してください。
* メイン画面の「デバッグ用 · レベル変更」は動作確認用です。経験値と服が初期化され、玉数は維持されます。

## ブランチと反映の流れ

1. 作業は自分のブランチで行う。

2. 作業を始める前に、最新のmasterを自分のブランチにマージする。

3. マージやpullの前に、必ず自分の変更をコミットしておく（未コミットのままだとEGitでエラーになります）。

4. 自分のブランチにpushする。masterへの反映はリーダーが行う。

* ブランチの最新化と動作確認は各自の責任で行う（リーダーは確認しません）。失敗したら自分のブランチを巻き戻して、もう一度やり直す。

## 動かないとき・おかしいときの確認順

上から順に試してください。それでも直らなければ、下の手順でAIに質問してください。



1. 自分のブランチに最新のmasterをマージしたか

2. Eclipseのメニュー「プロジェクト」→「クリーン」を実行する

3. 「サーバー」ビューで Tomcat10_Java21 を選び、右クリック→「クリーン…」を実行してから再起動する

4. ブラウザで動作確認URL（?reset=true 付き）を開き直す

5. エラーが出ているなら、エラーメッセージ（コンソールの赤い文字）を全文コピーしておく

## AIにプロジェクト全体を共有する方法

※ トラブルシューティングや実装相談をする際は、以下の手順でコード全体をAIに渡してください。



1. バッチファイルを実行する

   * プロジェクト直下にあるバッチファイル（export_all.bat）をダブルクリックして実行する。

   * build フォルダ内に all.txt が自動生成されます。

2. 生成された build/all.txt をAIにドラッグ＆ドロップする。

3. 質問するときは、次の情報を一緒に添えて送る：

   * やりたかったこと と 実際どうなったか

   * エラーメッセージの全文（コンソール等の赤文字）

   * 画面表示の崩れやUI相談なら、ブラウザ画面のスクリーンショット

   * ※ 画像ファイル（images フォルダ）、サーバー定義、ビルドパス設定は all.txt に含まれないため、該当箇所のスクリーンショットを添付する

4. 【重要】all.txt は build フォルダ内に生成されるため、Git管理されません。不要になったら削除してください。
